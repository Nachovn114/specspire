# Fase 0 · Preparar / constitución

**Resultado:** contexto acordado: qué se hará, para quién, restricciones, reglas y qué queda fuera. Se registra en `PROJECT.md` si existe; si falta (instalación solo Skill), se mantiene en la conversación hasta que el desarrollador autorice crear o guardar un documento.

1. Inspecciona repo, rúbrica y tecnología disponible; no borres estructuras existentes.
2. Identifica si es proyecto nuevo, cambio o bug. Elige alcance ligero, normal o riguroso según riesgo real.
3. Registra el contexto sin inventar, en `PROJECT.md` o en la conversación según el punto anterior; marca lo desconocido y los requisitos obligatorios.
4. Aplica principios: KISS/YAGNI, modularidad práctica, testabilidad, seguridad, accesibilidad, documentación mínima y control de versiones.
5. Para aplicaciones grandes, puedes ampliar la constitución; para una tarea académica basta el archivo corto.

**Gate:** objetivo demostrable, límites y reglas claros; dudas bloqueantes identificadas.

**Prompt:** «Revisa mi proyecto/rúbrica y resume el contexto con hechos, separando lo que todavía falta decidir. Si existe PROJECT.md, complétalo; si no, pregúntame antes de crear archivos. No crees código».
