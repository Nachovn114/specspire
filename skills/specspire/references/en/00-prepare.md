# Phase 0 · Prepare / Constitution

**Outcome:** Agreed context: what will be built, for whom, constraints, rules and non-goals. Record it in `PROJECT.md` if it exists; otherwise (Skill-only installation), keep it in the conversation until the developer authorizes creating or saving a document.

1. Inspect repo, rubric and available technology; do not delete existing structures.
2. Identify whether this is a new project, change or bug. Choose lightweight, standard or rigorous scope based on actual risk.
3. Record context without hallucinating, in `PROJECT.md` or in conversation according to the previous item; flag unknowns and mandatory requirements.
4. Apply principles: KISS/YAGNI, practical modularity, testability, security, accessibility, minimal documentation and version control.
5. For large applications, you may expand the constitution; for an academic task, the short file is sufficient.

**Gate:** Demonstrable objective, clear boundaries and rules; blocking uncertainties identified.

**Prompt:** "Review my project/rubric and summarize the context with facts, separating what still needs to be decided. If PROJECT.md exists, complete it; if not, ask me before creating files. Do not write code."
